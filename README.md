# СОНИКС — приветственная страница

Локальный прототип на React, TypeScript и Vite с настоящими компонентами Soniks Design System.

```sh
bun install --frozen-lockfile
bun run dev
```

Проверка типов и production-сборка: `bun run build`. Предпросмотр сборки: `bun run preview`.

## Дизайн-система

Подключены `@sonik-space/ui`, `@sonik-space/icons`, `@sonik-space/tokens` версии 0.1.6.
Пакеты собраны без изменений из https://github.com/sonik-space/soniks-design-system
на коммите `6c2be4e32c68ea9891e68fc72b46f66acf7e299e` и сохранены в `vendor/`.
Это локальная сборка исходников, а не подтверждённый релиз из реестра.
GitHub Packages отклонил установку: текущему токену не хватает `read:packages`.
Для запуска не нужны токены или исходный checkout дизайн-системы.

Используются публичные Button, ThemeToggle, фирменный логотип, иконки и CSS-токены.
Inter и Roboto Mono поставляются локально через Fontsource.
Тема сохраняется в localStorage.
Главная сведена к одному экрану: хедер UI-кита, заголовок, подпись,
ссылка на открытый код, кнопка перехода к станциям и монохромный глобус.
Глобус показывает станции из публичного `https://sonik.space/stations_all/`.
Вращение работает мышью, касанием и стрелками. Фильтры, поиск, карточки,
масштабирование и дополнительные промосекции убраны.

`vite.config.ts` проксирует `/api/sonik/stations` с необходимым AJAX-заголовком
при `dev` и `preview`. Данные обновляются при открытии страницы. При ошибке используется `public/data/stations.json`; дата копии
явно показывается на странице. Для размещения `dist` на обычном статическом
хостинге нужно настроить аналогичный прокси, иначе используется копия.
Данные станций: СОНИКС, CC BY-SA 4.0. География: Natural Earth / world-atlas.
Глобус реализован на d3-geo, без использования чужого Mapbox-токена.
Живые данные спутников и наблюдений не подключены.

## Создание станции

`/stations/new` — форма с тремя этапами: расположение, антенны, описание и фотографии.
Ссылка «Создать станцию» находится внизу главной страницы.
Проверяются обязательные поля, диапазоны координат и частот. Минимальный горизонт по умолчанию — 0°.
Можно добавить от 1 до 10 антенн и до 10 фотографий с выбором главной.
Описание и фотографии необязательны. Частоты вводятся в МГц.

Станции вместе с файлами фотографий сохраняются локально в IndexedDB (`soniks-prototype`, хранилище `stations`).
Публикация на сервер СОНИКС не подключена. Очистка данных браузера удалит локальные станции.
Проверка правил формы: `bun test src/station/model.test.ts`.

## Файлы

- `/design-system` — каталог типографики и компонентов; ссылка есть внизу главной страницы.
- 2 семейства шрифтов, 33 текстовых стиля и редактируемый текст образца.
- 73 группы и 277 примеров из оригинального Storybook; поиск, состояния, тема и ширина предпросмотра.
- `/component-library/` — полный Storybook с документацией и Controls.
- `public/component-library/` — автономная статическая сборка каталога из того же коммита, что и пакеты. Для запуска не нужен внешний сервер Storybook.
- `src/typography.json` — параметры из `packages/styles/src/_typography.scss`; совместимые алиасы не дублируются.
- `bun run catalog:update` — заново собирает каталог из зафиксированного коммита (нужны Git, Bun и доступ к сети). Обычные `dev` и `build` используют сохранённую сборку.

Каталог воспроизводит исходные stories системы. Вспомогательные компоненты показаны внутри составных примеров; для каждого внутреннего элемента отдельная story в исходном репозитории не предусмотрена. Демонстрационные callback-обработчики и данные сохраняют поведение оригинальных stories.

- `src/main.tsx` — приветственная страница и взаимодействия.
- `src/styles.css` — адаптивная композиция с токенами Soniks.
- `vendor/` — переносимые архивы оригинальных пакетов.

## Обновление локальных пакетов

В отдельном checkout дизайн-системы на нужном коммите:

```sh
bun install --frozen-lockfile
bun run build:packages
```

В каждой из папок `packages/tokens`, `packages/icons`, `packages/ui`:

```sh
bun pm pack --ignore-scripts --destination /absolute/path/to/sonik-prototype/vendor
```

Обновите пути версий в `package.json`, выполните `bun install` и `bun run build`.
Для перехода на опубликованные пакеты используйте инструкции `docs/releasing.md`
исходного репозитория и токен с `read:packages`, передаваемый через окружение.
Не сохраняйте секреты в проекте.
